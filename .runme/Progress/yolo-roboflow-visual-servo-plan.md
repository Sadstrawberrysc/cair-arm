### 1.1 无标记定位的具体对象

**用户约束：不放置可见标记，使用 YOLO 从自然 RGB 画面定位。**
已确认腕部视野：能看到下颌和颈部边界，看不到锁骨。因此主路线确定为腕部
YOLO-Pose 直接定位，训练画面与部署视野一致；不把锁骨设为必需输入或标签。
结合本仓库颈动脉超声扫查任务，模型目标定义为：
**选定侧颈部体表的初始扫描点 `scan_start`，只预测这一个目标点。**
目标是让机械臂对准预定的皮肤位置，随后由深度提供表面几何并完成视觉伺服。
该点表示依据体表外观估计的接近位置；实际血管位置和成像质量需用超声核验。

建议首版用 YOLO-Pose，Roboflow 建 `Keypoint Detection` 项目，类别只设
`carotid_scan_region`，实例内只标一个关键点 `scan_start`。标准 YOLO-Pose 格式
所需的实例框用于训练和内部候选筛选；对外定位结果仅为初始扫描点像素及其
置信度，例如 `scan_start: [u, v], confidence: c`。框不作为额外的控制目标输出。
本轮操作哪一侧由操作员设置的任务配置决定，不能从腕部小视野或画面左右擅自推断人体左右。

| 唯一关键点 | 具体定义 | 用途与真值依据 |
| --- | --- | --- |
| 0 / `scan_start` | 预定首个扫查位置对应的皮肤表面点 | 替代人工点击；标签来自统一扫查协议下的专家示教位置与相机配准 |

模型的 RGB 输入主要利用已确认可见的下颌轮廓与颈部边界，并结合皮肤纹理、
褶皱及实际可辨的胸锁乳突肌外观。训练图保留这些上下文，不能提前裁成只有小片
皮肤的 ROI；不要求出现锁骨。不能假设每个人都有清晰的肌肉边缘，也不能把体表
轮廓当成真实血管边界。标准 COCO 人体关键点
没有这个自定义扫描点，需要用自己的数据训练；不能直接调用预训练人体 Pose
模型得到颈动脉扫查位置。

训练实例框以配准后的 `scan_start` 为参考：按统一物理半径取目标附近表面邻域，
投影到图像后生成轴对齐包围框；半径依据探头尺寸及接近误差预算选定并写入数据
规范。框不能退化成零面积，也不能由标注人员随手圈不同大小的“脖子”。完整 RGB
图像仍保留下颌和颈部边界上下文。单点预测精度通过独立受试者测试验证。

### 1.2 没有可见标记，如何得到可信训练标签

示教任务定义为“确定选定侧的初始扫描位置”；起点选择
必须由同一采集协议约束，不能让专家每帧任意点一个位置。具体有效扫查位置由专家
超声示教确认，记录探头接触中心/姿态、对应 RGB-D 和时间，再通过已验证坐标链
把皮肤参考点投影到相机。单个关键点和训练实例框从这些测量生成，在 Roboflow 中复核。

**标注点不需要在皮肤上画出来，但必须有可靠测量来源。**探头遮挡目标时，应在目标
身体姿态稳定的条件下采集探头移开后的 RGB-D，并核验表面对应；接触压力引起的
形变、移开后的回弹或两次采集间人体运动必须计入标签误差，无法可靠对应的样本
剔除。皮肤表面点与超声图像中的血管中心属于不同位置，不能直接互换坐标。

每个训练点记录专家示教来源、对应原始 RGB-D、时间和测量误差；测试真值由
独立专家复核或独立测量取得，不能把模型自身预测当成验证依据。仿体可用于几何、
通信和闭环调试；验证自然人体 RGB 定位的泛化仍需独立主体的数据。

### 1.3 腕部相机视野与定位条件

| 到达初始位置后的实际画面 | 实施路线 |
| --- | --- |
| 下颌/颈部边界及真实初始点同时在视野内，点处有有效深度和跟踪边距 | 腕部 YOLO-Pose 从当前 RGB 预测初始扫描点，同步深度求几何 |
| 只看到缺少辨识特征的一小片皮肤 | 暂停定位并调整腕部观察位置，使下颌、颈部边界与目标皮肤重新入镜，再从新 RGB-D 运行 YOLO；观察位置变化需验证对应图像分布 |

用户已确认“可见下颌和颈部边界、不可见锁骨”，但 2026-09-25 又确认真实目标点
位于当前视野外。因此当前取景不满足第一条路线；必须先让真实目标进入视野，
并保留足够的下颌/颈部边界上下文，再验证腕部直接定位。先采集试标图验证下颌、颈部边界和
目标点能同时入镜，以及不同头部转角下是否可重复标注；第二条路线只作为后续
发现上下文丢失时的备选。运行中轮廓离开视野时拒绝重新定位，不依靠旧框猜目标。

YOLO 候选点直接接入腕部 `ClickSession`，绑定当前图像采集时间和机器人会话。
开始跟随后只用实时观测及局部追踪核验目标一致性，不额外读取外部路径或目标种子。

### 1.4 从预测结果到机械臂观测

1. `scan_start` 像素与同步、对齐深度得到相机坐标三维表面点；邻域皮肤点云
   拟合外法向。模型输出一个二维初始扫描点，RGB-D 负责三维恢复与表面测量。
2. 向现有 Robot v1 接口发送该点和外法向。Robot 由法向确定 Tool-Z，沿用已有
   Tool-X 连续姿态规则；该朝向来自几何和控制器，不是模型预测的扫查方向。
3. 对同一目标开始跟随后，使用局部跟踪维持同一个皮肤点；周期性 YOLO 核验
   初始扫描点的一致性。不能把每帧变化的检测框中心当成同一个皮肤点直接驱动。
   重新检测与已跟踪点不一致时记录偏差并进入重新确认流程。

## 2. 当前接口与姿态语义

| 项 | 现状 / 接入约束 |
| --- | --- |
| 相机 | `Gemini 305`，当前彩色 MJPG 与深度 Y16 均为 640×480、30 FPS；深度对齐彩色，使用实际流内参、深度尺度和单调采集时间。|
| 观测 | `robot:wrist:observation:v1`：相机光学系 `point_camera_m`、`normal_out_camera`、`pixel`、`quality`、`capture_monotonic_ns` 等；Robot 检查目标 ID、boot、外参 SHA、序号、时效和质量。|
| 控制 | `robot:wrist:command:v1`：`begin/resume/pause/end/heartbeat`；首次自动识别只产生候选，用户确认后才发 `begin`；丢失后新目标需显式 `resume`。|
| Robot | `T_base_camera(t)=T_base_armtip(t)·T_armtip_camera`；`p_goal=p_surface_base+0.050 n_out_base`，Tool-Z 指向体内。Robot 按采集时刻插值，不接受过期观测。|
| 已知边界 | 腕部外参仍为候选、未独立验收；当前真实运行与空间/时序问题见 `camera-wrist-progress.md`。模型上线不能跳过这些验收。|

Ultralytics 的 `pose` 指的是图像关键点任务，通常输出二维像素关键点；`detect` 输出
二维框，`segment` 输出二维掩码。它们都不直接提供 RM75 所需的六自由度位姿。
本任务只训练一个二维关键点。三维位置由同步且对齐的深度/内参求出，表面法向
由局部三维点拟合；Robot 沿用现有姿态连续性规则生成朝向。

## 3. 工作包与交付门

### P0 — 目标与测量协议（开始数据采集前）

1. 按 1.1 的单个初始扫描点定义，先采集 20～30 组无标记 RGB-D 样例，保留
   下颌和颈部边界上下文。按 1.2 复核示教点的投影误差、训练框范围、可标注性
   和深度质量；按 1.4 验证单点及表面法向与既有控制接口的衔接。
2. 定义判定规则：多目标时优先级、检测到目标但深度无效时的处理、目标被遮挡
   或离开视野时的处理、置信度不足时的处理。首版均为“不发布有效观测/Hold”，
   不自动跳到另一个目标。
3. 将数据处理范围、被摄者授权及 Roboflow 工作区可见性确认后再上传图像；
   原始 RGB-D、人体影像、日志和 API Key 留在受控位置，密钥不写入仓库。

**交付**：一页标签规范（类别、初始扫描点、训练框、遮挡和负样本定义）、目标点
真值采集流程和明确的人工确认动作。若无法从可见 RGB 特征重复标出目标，先调整
视野/标签获取流程，再开展训练。

### P1 — RGB-D 数据采集与 Roboflow 标注

1. 采集与真实入口相同的 640×480 彩色、对齐深度、内参、深度尺度、采集时间、
   相机序列号、机器人状态和外参摘要。采集覆盖不同受试者/体位、肤色、光照、
   工作距离、接近角、探头/手臂遮挡、运动模糊、背景和无目标场景。不要只从
   连续视频随机抽近邻帧充数；保留独立短序列供时序验证。
2. 用 Roboflow 建私有 `Keypoint Detection` 项目，类别为 `carotid_scan_region`，
   唯一关键点为 `scan_start`；按 1.1/1.2 的几何规则生成框和点。
   `kpt_shape: [1, 3]`，核对导出的可见性语义，并记录遮挡情况及标签测量误差，
   不以“皮肤上没有画点”等同于目标被遮挡，无法取得可靠坐标的点不得编造。
   先标 100～200 张试标集并双人复核歧义，再扩大；把无目标、相似组织、遮挡、
   深度孔洞及相似皮肤区域作为难例。数量是采集起点，不是准确率保证。
3. 同一次采集、同一受试者/场景的相邻帧只放一个 split；按会话/对象划分
   train/val/test，测试集冻结。保留原始图像到 Roboflow 版本 ID 的映射、标签规范
   版本及标注审查记录。预处理只与部署输入一致；几何增强若改变关键点位置，
   核对标签同步变换，避免把深度几何与 RGB 增强后的图像错配。
4. 生成固定 Roboflow 数据集版本，导出对应 Ultralytics YOLO 任务格式；核对
   `data.yaml` 的类名、split、关键点顺序/可见性，以及随机抽样可视化。
   导出图像标签只用于训练；实际三维验收须回到原始同步 RGB-D。

**交付**：Roboflow 项目/版本号、split 清单、标签质检摘要、导出包校验值和
冻结测试序列；原始影像/权重不纳入 Git。

### P2 — Ultralytics 基线训练与离线评估

1. 在独立训练环境记录 `ultralytics`、PyTorch、CUDA、驱动和模型权重的精确版本。
   先用轻量 Pose 预训练模型做基线（例如 `yolo11n-pose.pt`，重训为一个自定义关键点），
   显式固定模型文件、随机种子、`imgsz`、epochs、batch、增强与数据集版本；
   不将文档首页的“最新型号”当作项目版本锁定。先验证导出标签可被读取。
2. 以 `yolo pose train model=yolo11n-pose.pt data=<data.yaml> ...` 训练，
   用 `yolo pose val model=<best.pt> data=<data.yaml> split=test` 在冻结测试集评估，
   具体参数以安装版本的 CLI 帮助和数据任务为准。保存配置、权重 SHA、混淆/错误
   样本、每类 Precision/Recall、mAP 和推理延迟；重点记录初始扫描点像素误差、
   三维定位误差、漏检率和错误目标接管率。
3. 与简单基线比较：人工点、区域规则/传统视觉和纯 YOLO 直接中心点。重点看
   **可执行目标**的错选率，而不是仅看 mAP。逐组报告相机距离、场景、遮挡、
   深度质量和主体差异；达不到门限时优先补对应难例，再考虑更大模型。

**建议首轮门限（P0 后按目标尺寸与实际误差预算确认）**：冻结测试集上目标点
P95 ≤8 px、错选可执行目标 ≤0.5%、无目标场景误触发 ≤0.5%；这里的像素指标
不能代替三维/控制指标。留出充足负样本，给出分母和置信区间；样本不足时标记
“待验证”，不得用零误报宣称达标。

### P3 — 三维目标与相机适配器

1. 在 `infer/Carotid_begin/` 实现模型适配层，输入与 `click_follow.py` 一致的 RGB-D
   帧，对外提供 `scan_start` 像素与置信度，并附 `target_id`、采集时间和模型版本。
   模型实例只加载一次；同一帧中多候选按 P0 规则选择，并锁定当前目标身份。
2. 对目标像素检查边界、对齐深度、有效点数和深度连续性；用当前内参反投影，
   复用/提取 `LocalTracker` 的局部平面拟合与朝相机外法向规则。预测的初始扫描点落在
   孔洞/背景时不得直接取单像素深度；使用目标附近的有效表面估计并记录偏移。
   实际目标取预测的 `scan_start`，框中心只作为对照基线。
3. 检查候选点/法向的有限值、`z>0`、法向单位长度、`n·p<0`、深度范围、平面 RMS、
   点数、帧间位置跳变和法向连续性。质量字段必须真实反映测量：若 YOLO 方案不使用
   LK 特征，不得伪造 `feature_inliers` 满足现有 Robot 门限；需明确修改协议和 Robot
   校验，或仍由 `LocalTracker` 生成满足现有语义的跟踪结果。
4. 首版优先“模型初始化/重捕候选 + LocalTracker 每帧跟踪 + 模型周期核验”；
   模型推理较慢时不能用旧框冒充新帧。任何推理超时、检测失效、目标身份改变、
   局部追踪失败，发布 `valid=false` 并保持/进入 Hold，记录原因和诊断图像。

**交付**：可离线重放的“RGB-D → 候选 → 3D 点/法向 → 现有 observation schema”
适配器与针对孔洞、错位、时间戳、反向法向、多目标/目标切换的回归测试。附与
人工选点或测量夹具对照的三维误差表；法向角误差和端到端延迟单独报告。

### P4 — 接入现有会话并分级联调

1. 在 `click_follow.py` 增加可选模型选点模式，保持人工点击模式可用。
   自动检测只在 Robot 状态有效、标定摘要匹配、无正在跟随的目标时提出候选；
   画面显示目标、置信度、深度/法向质量、控制状态。操作员确认候选后才生成
   新 `target_id` 并按原 `begin` 流程开始。丢失后必须重新确认并 `resume`。
2. 复用 `ClickSession` 公共字段、单调序号、心跳、会话和 boot 检查，不另开
   能绕过 Robot 的控制通道。模型/标注/权重 SHA 和测量质量写相机 JSONL；
   Robot 日志继续记录观测年龄、插值跨度、规划/拒绝、实际间距和停止原因。
3. 逐级验收：离线录像回放 → 本机 Redis/Robot 隔离仿真（ServoJ 发送数 0）
   → 实机仅观测 → 真机悬停但不接触 → 低速受控跟随。每级做静止、缓动、
   多目标、遮挡、光照变化、深度缺失、相机断流、Robot 重启和进程退出。
   每级保存原始日志及摘要，前一级不过不进入下一阶段。
4. 真机前独立复核 Gemini→ArmTip 外参、TCP 几何、同一测量参考点多姿态 Base 位置、
   RGB-D/Robot 时序、约 80 mm 相机工作距离和 TCP 到表面净空；特别复核历史
   空间差值与抖动。先按现有操作手册检查停止链路与操作员可达的急停。

**建议闭环验收**：在事先定义的工作区、主体/会话分组和目标运动范围内，逐次
记录目标点三维误差、法向角误差、稳定段 TCP–表面间距、P95/P99 端到端延迟、
跟踪丢失恢复次数、错误目标接管次数、Robot Hold/Fault 及实际运动轨迹。
目标值由 P0 的误差预算和现场安全评审确定；任何无效观测导致继续追新目标、
超时后继续运动或未确认恢复，均判失败。若要探头接触/超声成像，另设力控和
成像质量验收；当前无力腕部模式只对应非接触悬停。

## 4. 建议的实施顺序与决策点

| 顺序 | 预计投入* | 完成判据 / 依赖 |
| --- | --- | --- |
| P0 | 2～4 天 | 目标可观测、标签一致性和误差预算已定义 |
| P1 | 1～3 周 | 固定版本数据集、独立测试集和标注质检通过 |
| P2 | 3～7 天 | 冻结集评估及错选分析完成；不过则迭代 P1 |
| P3 | 1～2 周 | 同步 RGB-D 到有效三维观测的离线重放通过 |
| P4 | 1～2 周以上 | 分级验证、空间时序核验和真实日志达到预定门限 |

注：粗估为有设备、标注人手及训练算力时的工作日/自然周量级；标注目标歧义、
设备稳定性、外参复核和现场测试可能成为关键路径，不能按表承诺上线日期。

首个可开工动作：从已完成的初始位姿保存 20～30 组同时包含下颌、颈部边界和
目标皮肤的无标记 RGB-D，按统一示教协议生成 `scan_start` 单点试标。
首先验证当前腕部视野下的 YOLO 直接定位；锁骨不纳入必需标签，必要时调整腕部观察位置。
